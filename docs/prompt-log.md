# 提示词与 AI 使用记录导出说明

## 1. 已提供的材料

| 材料 | 位置 | 说明 |
|---|---|---|
| 结构化事件清单 | `docs/events.jsonl` | 由 `git log` 与 GitHub Actions API 真实数据生成，按时间排序，含提交、CI 成功/失败、制品、本轮修复 |
| AI 使用说明 | `docs/ai-usage.md` | 阶段分工、学生审核内容、有记录的纠错 |
| Agent 约束 | `AGENTS.md` | 首次提交 `e944712` 入库，后续按实测更新（`2b59e59`） |
| Skill 与调用记录 | `skills/*/SKILL.md`、`docs/skill-usage.md` | 自编 Skill 内容 + 实际命令输出 |
| 验收与缺陷 | `docs/verification.md`、`docs/workitems.md` | 16 场景记录、5 条缺陷与修复提交 |

## 2. 无法自动导出的范围（如实声明）

IDE 会话（含全部提问、补充上下文、纠错要求、Agent 可见回复、工具调用明细）由客户端本地保存，未提供可按会话批量导出的公开接口，因此：

- **未提供**逐条提示词原文与逐条工具调用日志的完整导出；
- 未获取平台隐藏指令与模型隐藏推理（按规范无需获取）；
- 上表材料只能证明"做了什么、结果如何"，**不能**证明"当时每一句提示词怎么写"。

## 3. 补证方式（学生执行，任选其一）

1. 在 IDE 会话面板中对本次开发、测试、验收三个会话分别执行「导出会话」，保存为 Markdown 放入 `docs/sessions/`；
2. 或对会话列表与关键提问截图，按阶段命名（`01-需求.png`、`02-开发.png`…）放入 `docs/sessions/`；
3. 导出后在本文件补一张索引表：会话名 → 对应阶段 → 对应提交 → 文件路径。

## 4. 补证后的自检

- 三个角色（开发/测试/验收）会话必须是相互独立的上下文，不得共用一个会话；
- 会话中的代码版本需与 `docs/events.jsonl` 的提交哈希对得上；
- 会话导出需脱敏（数据库口令、令牌一律打码）。
