# 需求说明 — 题目 02：宠物门店的预约、接待、服务与取消退款

> 阶段：需求分析（依据《Go项目业务场景题.md》题目 02 与 `AGENTS.md` 硬约束）
> 本文档回答：角色是谁、业务怎么发生、规则边界在哪、异常如何收尾、怎样算验收通过。

## 1. 角色与业务起点

| 角色 | 职责 | 预置账号 |
|---|---|---|
| 店长 | 发布可预约时段、标记未到店、查看预约与经营结果 | `owner` |
| 宠物主人 | 为自己的宠物预约、付款、取消、查看服务结果 | `user1` / `user2` / `user3`（各 1 只宠物） |
| 前台及服务人员 | 核验到店（核销）、登记服务开始与完成 | `front`（绑定门店 S001） |
| 客服 | 审核临近开始时间的取消申请、跟进退款失败、处理异常支付 | `support` |
| 模拟支付渠道 | 受理支付/退款，报告成功、失败、超时、重复通知 | — （独立进程 pay_sim） |

预置数据（题面固定）：1 家门店（S001）、1 个洗护项目（预约款 9900 分）、3 个未来时段（14:00–15:00 / 16:00–17:00 / 18:00–19:00，每时段 3 个名额，名额全局共享）。宠物档案只读，不实现新增编辑。

## 2. 主流程与状态机

```
预约提交 → 待支付 PENDING_PAYMENT（预扣名额，5 分钟支付有效期）
  ├─ 超时未支付 / 主人主动取消 → 已关闭 CLOSED（释放名额，幂等）
  └─ 支付校验通过 → 已确认 CONFIRMED
        ├─ 分支A 履约：核销 CHECKED_IN → 服务中 IN_SERVICE → 已完成 COMPLETED
        ├─ 分支B 取消：提交取消申请 →（距开始 ≥2h 自助全额退款；<2h 客服审核）
        │     ├─ 审核通过 → 已取消 CANCELLED（退款，名额原路释放一次）
        │     └─ 审核拒绝 → 回到 CONFIRMED（名额解锁，可正常核销）
        └─ 分支C 未到店：时段结束仍未核销未取消 → 店长手动标记 NO_SHOW（不可回退）
```

互斥：分支 A 与分支 B 不能并存。已核销 / 服务中 / 已完成的预约不再受理取消退款。

## 3. 业务规则（题面 8 条 → 实现口径）

1. **时段与预约资格**：时段必须有明确起止时间和名额；不可预约条件（任一命中即拒绝，前置强制校验）：名额已满、时段已开始（当前时间 ≥ 开始时间）。同一宠物同一时段仅 1 条有效预约；同一宠物任意两个预约服务时间区间重叠即冲突拦截。
2. **待支付与支付**：提交预约立即预扣名额，占用 5 分钟，计时起点为订单创建时间，不支持重置倒计时；超时或主动取消即关单释放名额（释放幂等）。有效支付通知须鉴权、匹配订单与金额；重复通知不重复确认；同订单多笔支付第一笔有效其余入异常支付台账；关单后收到支付成功 → 异常支付列表，客服核实后退款，不恢复预约、不返还名额。
3. **取消两分支**：距服务开始 ≥2h → 主人自助取消、全额退款；<2h → 必须填写取消原因（空内容拒绝提交），提交后进入审核：审核期间名额持续锁定、禁止核销；通过 → 执行退款；拒绝 → 写明拒绝原因，解锁名额，回到已确认。
4. **退款规则**：退款渠道确认成功后名额原路释放一次（幂等）；退款回调超时阈值 7 自然日，超时订单保持「已取消-退款处理中」并留在客服待跟进；退款最多重试 3 次，全部失败标「退款终态失败」，不再自动重试；退款状态独立可查询，退款失败不使预约复活。
5. **核销履约**：仅可核销本店（前台账号绑定门店 ID）、已确认且无「审核中」取消申请的预约；流程强制 核销→服务开始→服务完成，禁止跳步，允许跨天完成；三步全部幂等（重复提交返回成功，不重复记收入）；核销与取消并发以先落库为准（数据库层加锁）。
6. **未到店**：时段结束时间到达后店长才可见「标记未到店」；必须店长手动操作、写明原因；标记后原因可编辑、状态不可回退；不自动退款、不自动释放名额；主人可查看。
7. **日清统计**：店长查询当日各时段有效预约/已完成/取消/未到店/退款待处理记录；已收款 = 支付成功金额（不含异常支付）；已退款 = 退款回调成功金额；实收 = 已收款 − 已退款；未到店已收款不计入已完成服务收入，单独统计；时段归属按【时段开始时间】所在自然日。
8. **权限**：不能通过修改请求中的用户/订单编号越权；主人仅能操作自己宠物与自己订单；前台仅本店；客服仅取消审核/退款跟进/异常支付；店长仅时段与经营管理。

## 4. 边界与异常（必须可操作、可持久化）

- 并发抢最后名额：数据库层原子扣减（`UPDATE ... WHERE remaining > 0` + 事务），失败方明确报"名额不足"。
- 同宠物并发预约同/重叠时段：唯一约束 + 区间重叠检查，只成功一条。
- 重复核销/重复开始/重复完成：幂等返回原状态。
- 核销 vs 取消审核提交并发：先落库者定结果，另一方被拒绝并提示。
- 重复支付回调、迟到支付回调、退款回调成功/失败/超时 7 天：均有台账与去向。
- 待支付 5 分钟超时：教学时钟可拨快触发；重复关单不重复释放。

## 5. 可验证的验收条件（对应题面 5 组完整场景）

1. **正常接待**：店长发布时段 → 主人预约付款 → 前台核销 → 登记 开始/完成 → 主人与店长查询结果一致，营收含该单。
2. **名额循环**：并发预约抢位（≥5 请求 / 剩余名额）→ 部分成功；未付款超时关单释放名额 → 新用户预约成功；释放次数正确（幂等）。
3. **取消分支**：≥2h 自助取消全额退款；<2h 提交原因 → 客服批准（退款+释放）与拒绝（解锁+可核销）各演示一次；退款失败 → 重试 ≤3 次 → 终态；用户能看到各自结果。
4. **门店现场冲突**：取消申请与核销并发仅一种合法结果；重复核销不重复记收入；非本店前台核销被拒。
5. **收店核查**：同日同时存在已完成、取消退款、未到店、退款失败记录；店长页分别核查，已收款/已退款/实收口径与记录一致。
