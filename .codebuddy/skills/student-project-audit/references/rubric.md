# 单题评分与合格规则

## 固定权重

| 编号 | 评分项 | 满分 | 按什么给分 |
| --- | --- | ---: | --- |
| A1 | 完整业务场景与角色闭环 | 3.00 | 本题全部角色、规则和五组完整场景，主流程、分支、人工处理与结果核查能实际完成 |
| A2 | 数据、权限与异常正确性 | 1.80 | 持久化、重启、状态/金额/数量、时间、并发幂等、失败处理和角色/租户边界正确 |
| A3 | 测试与质量验证完成度 | 1.70 | 有真实有效断言，覆盖全部业务及异常，整体/核心包单元覆盖率达标，相关检查和复测有据 |
| A4 | 可运行交付、上线与视频 | 1.50 | 可复现运行及演示数据、真实自动发布和版本对应、上线业务验证、完整讲解效果与当日群交付 |
| B1 | 开发顺序与角色交接 | 0.60 | 七阶段前置关系和修复循环合理，独立测试验收、版本及交接真实 |
| B2 | Agent 约束与 AI 提示执行链 | 0.80 | 约束提前编写加载，全部关键步骤可追溯、合理使用上下文及工具、审核与纠错有效 |
| B3 | 自编及实际使用 Skill | 0.30 | 自编结构与场景适配，全部已用 Skill 的位置/原因/帮助有调用和结果证据 |
| B4 | MCP/Git/工作项规范 | 0.30 | MCP 建仓、开发分支、原提交规范、真实编号、PR/保护/合并门禁均可核实 |
| 合计 | 成果 8.00，过程 2.00 | **10.00** | 先检查 A，再检查 B |

先拆为要求原子项，每个指定分类、满分及 mandatory。每类原子满分合计必须精确等于该类固定满分；分值用两位小数字符串，不使用浮点累计。原则上同类适用原子要求等权；无法用两位小数均分时按要求编号顺序分配剩余 0.01，并在检查前锁定。若教师另有明确单题权重，先登记映射，保持本表类总分，说明依据，不根据学生表现重分配。

对源码行为或成果应给分的要求，归 A；对原执行顺序、提示、约束、Skill 和 Git 操作，归 B。一个故障可影响多个不同要求，但不得将同一要求拆成多个同义扣分项。

数值上的满分同时要求基本可维护、清晰的证据和解释，而非额外堆技术。可选加固/质量优化只能在题面或教师明确存在此类可选评分要求时列为 `mandatory:false`；不能自行增加 UI 精美、复杂架构、额外组件等评分项。题面“必须、须、要求”的适用事项均为 mandatory，不能擅自降级为可选。

## 每个原子项的得分

- pass：全部完成，系数 1。
- partial：有证据证明部分完成，并明确剩余部分，系数 0.5；并不代表必做要求已经合规。
- fail：有反证，或完整检查确认该成果不存在，系数 0。
- unknown：证据不足无法判断，系数 0，列待补证，不写已证实没做。
- na：来源明确的不适用，给出触发条件和证明，在本分类剔除；不向其他分类转移分数。

每类得分 = 该类固定满分 ×（适用原子项满分 × 系数之和）÷ 适用原子项满分之和，权重用 Decimal 校验为两位小数，计分用 Fraction 有理数精确运算，中间不舍入。每类必须有适用项；分类全 na 时说明题面与评分表不匹配，不能自动送分，应先澄清依据。

## 合格规则与必做门禁

用户要求全部合规，同时要求 8 分及格，因此分开保留“原始成果与过程分”和“合规门禁”：

1. 原始分为八类精确分之和；未触发门禁时为最终分的计算基础。
2. **任何适用 mandatory 原子项不是 pass 时触发门禁**，逐条列出来源、事实/缺证、影响和证据。包括但不限于：关键场景不完整、覆盖率低于 85%、无实际部署、没有自编 Skill/实际调用、提示词关键步骤缺失、开发顺序违规、非 MCP 建仓、Git 不合规、没有完整讲解视频或群提交。
3. 触发门禁时最终分 = min(原始精确分, 7.90)，只统一封顶一次，不按门禁条数重复减分；解释原始分与封顶差额。原始分本已低于 7.90，不再额外减分。
4. 最终展示分向下保留两位小数，不将 7.999 四舍五入为 8。**最终分 ≥8.00 合格，低于 8.00 不合格**；无额外“分数合格但综合不合格”口径。
5. unknown 同样不能给通过，报告写“当前证据评分：不合格，待补证复核”，明确是未能确认，不暗示已经证实违规。因教师平台/权限造成的未知项单列阻塞归属，不指责学生操作错误；门禁经教师明确豁免才可记录豁免依据，不代替教师豁免。
6. 必做要求全部通过、另有教师明确可选质量项部分失分时，仍可能得 8～9.99 分；若没有可选评分项，全部达标可能就是 10 分，不为制造分布硬扣分。

## 必须解释高分或低分

每类输出满分、适用权重、已完成得分、失分、原子明细和证据。

高分说明：哪些完整业务及异常实测通过、为什么数据与权限可信、测试质量怎样、部署与视频如何对应最终版本、AI 与 Skill 具体有效在哪里。不得只有“完成很好”。

低分说明：具体未完成什么、在哪一步失败、少哪条证据、影响哪条规则、为什么得到相应系数；写出正确思路与最小整改及复查条件。未运行测试或未看视频不能编造结果。

## 计分输入结构

`audit-input.json` 至少包含 student、question、revision 和非空 checks：

```json
{
  "student": "学生标识",
  "question": "01",
  "revision": "实际提交哈希",
  "checks": [
    {
      "id": "R-唯一编号",
      "category": "A1",
      "max_points": "0.10",
      "status": "pass",
      "mandatory": true,
      "evidence": ["E-001"],
      "reason": "具体已完成与未完成范围及判定依据"
    }
  ]
}
```

此片段仅演示一个字段完整的原子项，完整输入必须覆盖八类且各类满分合计正确。na 另须 `condition`，表明未触发的题面条件；其余状态至少有一个可定位证据，unknown 可关联材料缺口/访问失败记录。证据编号须能在报告中解析，计分器不代替证据真实性与完整性审查。
